# 复现协议与边界

这套脚本针对固定小样本，不是支持任意FIREBALL文件的通用加载器。例如独立检查器明确要求25条记录；不要直接用于全库再将失败率解释成数据质量。

## 实际执行链

1. 下载或复用12个固定文件，逐一核验大小、SHA256和Git blob SHA1。
2. 审计raw事件引用、消息身份、状态边界、CRD3字段，输出schema/results.json和lineage.json。
3. 从固定且校验过的Avrae源码中用AST提取已检查的 `Combatant.hp_str` 方法，在仅含HP相关字段的对象上执行；没有导入或运行完整Avrae项目。
4. 分开输出行动前输入与观察到的目标/结果。输入只含行动者ID和最多20条早于当前动作的人类消息，排除机器人消息及所有结构化状态。按原始索引、message_id和created_at限制边界。
5. 分别扰动未来文本/结果、当前目标动作和结构化状态，检查每条输入不变；再由独立检查器核对原始行号、时间、内容、身份、去重与目标注入负对照。

执行产物均在 `outputs/`。`results/reference_summary.json` 是已完成检查的汇总；模型调用、GPU使用、付费API调用均为0。移植核查将FIREBALL和CRD3统计与2026-10-21旧脚本逐项比较，也将可见性统计与2026-10-22旧脚本比较。源文件验证从原7项扩展为12项，增加5份源码；算法与样本未改变。

## 解释限制

- `command_idxs` 含执行结果等多个事件，不能当作一组纯动作命令；日志行序也不等于动作发生顺序。
- `combat_state_update.human_readable` 是内部完整状态文本，不保证是公共频道消息。
- HP的private开关由固定版本源码核实；私聊、角色知识和其他属性的完整可见性尚未核实。
- 不知道信息与记录里没有信息是不同判断；GPT候选标注不能补造私有知识、最优动作或反事实奖励。
- 当前25条来自同一场战斗，没有独立测试集；75项扰动检查不是75个独立任务成功率。
- 不含在线环境、模型训练或OPD。历史动作上的监督学习属于离线训练；OPD还需要当前学生采样及有效教师反馈。

## 下一阶段

取得多个可追溯会话，核实角色观测和分组边界后，再确定可判定的协作任务。评测应比较同信息与同预算下的规则方法、单模型与多智能体；目前没有多智能体优于单模型的实验证据。
